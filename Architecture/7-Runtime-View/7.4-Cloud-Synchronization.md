# 7.4 Cloud Synchronization

<details>
<summary>Documentation Hints</summary>

Describe synchronization triggers, ordering, merge semantics, and error handling.
</details>

```mermaid
sequenceDiagram
    participant App
    participant Sync
    participant Local as Local stores and IndexedDB
    participant Cloud as Supabase

    App->>Sync: Login, visible tab, manual request, or ride finish
    Sync->>Sync: Skip if signed out or already running
    Sync->>Local: Normalize legacy H3 cells
    Sync->>Cloud: Read explored snapshot
    Sync->>Local: Insert cloud-only cells
    Sync->>Cloud: Upsert union of cells
    Sync->>Cloud: Read wallet counters
    Sync->>Local: Apply maximum counters
    Sync->>Cloud: Upsert maximum counters
    Sync->>Cloud: Read rides
    Sync->>Cloud: Upsert local-only rides
    Sync->>Local: Upsert cloud-only rides
    Sync-->>App: Synced timestamp or error status
```

The merge is monotonic: union and maximum operations avoid destructive conflict resolution. This also means incorrect or simulated local progress cannot be automatically subtracted after synchronization.
