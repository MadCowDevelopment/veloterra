# 9.3 Architecture and Design Patterns

<details>
<summary>Documentation Hints</summary>

Describe recurring patterns and their intended use.
</details>

| Pattern | Application |
|---|---|
| Layered modular frontend | Screens orchestrate focused map, state, persistence, and integration modules. |
| Local-first | Ride processing and persistence work without cloud availability or an account. |
| Adapter hook | Geolocation and Wake Lock APIs are wrapped by React hooks. |
| Observable store | Zustand stores publish auth, wallet, preference, and explored-state changes. |
| Revision signal | Explored state mutates its large cell map in place and increments a scalar revision for geometry changes. |
| Monotonic merge | Cloud reconciliation uses union and maximum operations. |
| Cache-aside / CacheFirst | Workbox serves previously cached basemap resources before network. |
| Build-time environment | `BASE_URL` defines routing, PWA scope, OAuth return URL, and worker asset paths. |
| Development substitute | Vite mode replaces real geolocation with map-click simulation. |
