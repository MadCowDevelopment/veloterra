# 9.5 Error Handling and Observability

<details>
<summary>Documentation Hints</summary>

Describe exception handling, user-visible failures, logging, tracing, and operational diagnosis.
</details>

| Area | Current Behavior |
|---|---|
| Geolocation | Permission denial and other failures become HUD statuses. |
| Wake Lock | Unsupported or failed acquisition is silently ignored. |
| Offline download | Abort is propagated; individual missing resources are skipped; UI owns progress/error display. |
| Cloud sync | A top-level catch sets sync status to error; overlapping runs are suppressed. |
| Cell persistence | IndexedDB write rejection is silently ignored after memory state changes. |
| Map styles | Fog layers are reattached after full style replacement. |
| Routing | Build copies `index.html` to `404.html` for GitHub Pages deep links. |

There is no centralized logging, telemetry, crash reporting, tracing, or health endpoint. Supabase response errors are not consistently inspected, so some failed operations may not enter the catch path.
