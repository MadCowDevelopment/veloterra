# 12.2 Quality Scenarios

<details>
<summary>Documentation Hints</summary>

Use stimulus-response scenarios with measurable acceptance criteria. Mark criteria not yet automated.
</details>

| ID | Source and Stimulus | Environment | Expected Response and Measure |
|---|---|---|---|
| QS-01 | Rider opens an installed app without network after preparing a region. | Supported mobile browser, service worker controlling page. | App shell opens and cached map assets render without a network dependency. Manual acceptance test. |
| QS-02 | Browser delivers a fix with accuracy above 35 m. | Active tracking ride. | Fix does not change distance, explored cells, or rewards. |
| QS-03 | Browser delivers an accepted fix in a new area. | Active tracking ride. | Current H3 cell and ring are processed locally; HUD/map update without awaiting cloud I/O. |
| QS-04 | Network or Supabase is unavailable. | Signed-in or signed-out ride. | Local ride tracking and persistence continue; sync may report failure and be retried. |
| QS-05 | Same user signs in on a second device. | Both devices contain different progress. | Explored cells and ride IDs converge by union; wallet counters converge to maxima. |
| QS-06 | User directly opens `/rides/{id}` on GitHub Pages. | Deployed application. | `404.html` boots the SPA and React Router resolves the route. |
| QS-07 | Developer opens Ride through the normal menu under Vite. | Development server. | Simulated GPS is ready without parameters; map clicks produce normal `GeoFix` processing. |
| QS-08 | User requests an offline region estimated above 100 MB. | Service worker active. | Download is blocked before bulk fetching begins. |
| QS-09 | Existing local cells have a finer H3 resolution. | Application load or sync. | Cells are consolidated to resolution 11 without reducing accumulated visits or rewards. |
| QS-10 | Main or dev is pushed. | GitHub Actions available. | Build must succeed before the corresponding Pages deployment runs. |
